# Реестр АПК: apk.db и живые запросы

## Два источника

1. **`_notes/apk-registry/apk.db`** — снапшот (быстро, без сети). Схема:
   `rules` (750; article/channel/priority), `mapping` (статья↔правило, 537),
   `rule_types`, `rule_errors` (+`error_no`), `errors` (800; fix_minutes),
   `acc_diagnostics` (691, снапшот 1.2.9.80 — описания и трудоёмкости),
   `article_status` (272), `backlog` (216), **`ported`** (координация конвейера).
   Пересборка: `python3 build_db.py` (таблица `ported` переживает пересборку).
2. **MCP `onec-apk-data`** — живая база АПК (`execute_query`, точечно и свежо):
   `Алгоритм` (код 1С правила — в apk.db НЕ хранится), `Описание/ОписаниеHTML`,
   ТЧ `ОбнаруживаемыеОшибки`, `ИспользуетсяПриПроверке`.

```sql
-- выбрать кандидата из бэклога (свободен, авто, канал bsl)
SELECT article, rule, name FROM backlog
 WHERE priority='P1' AND rule NOT IN (SELECT rule FROM ported) ORDER BY article;
-- прогресс конвейера
SELECT priority, COUNT(*) FROM backlog
 WHERE rule NOT IN (SELECT rule FROM ported) GROUP BY priority;
```

## Точечный запрос алгоритма правила (MCP onec-apk-data)

`execute_query` c `queryText`:
`ВЫБРАТЬ Код, Наименование, Алгоритм, Описание ИЗ Справочник.Правила ГДЕ Код = "АПК_00260"`
— вернёт markdown-таблицу; `Алгоритм` может быть длинным (несколько КБ).

## Грабли живой базы (проверено)

- `execute_query` **режет выдачу на ~100 строк** — пейджинг обязателен.
- В пейджинге `last` передавать **полное предыдущее значение** колонки
  сортировки (URL целиком, не хвост) — иначе цикл буксует на первой странице.
- `Код` справочника `Требования` — автонумерация (75 шт. «1»), **не** номер
  статьи. Номер статьи только из `СсылкаНаСтандарт`
  (`its.1c.ru/db/v8std#content:NNN:hdoc` → NNN).
- Неограниченную строку (`Алгоритм`) нельзя сравнивать с `""` в запросе.
- Снапшот устаревает (АПК развивается): перед взятием правила — точечный
  запрос в живую базу (не удалено ли, не изменился ли Алгоритм).

## Обновление снапшота

`python3 build_db.py` пересобирает apk.db из файлов-выгрузок
(`tool-output/*` прошлых прогонов). Полный переприём из базы — циклами
`execute_query` по 100 строк (см. историю: rules=750, mapping=537,
types=2500, errors=800+582) с сохранением больших выводов в файлы.
