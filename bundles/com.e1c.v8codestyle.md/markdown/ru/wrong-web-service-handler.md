# Отсутствующий обработчик операции Web-сервиса

Непустое procedureName операции должно ссылаться на существующий метод в модуле своего сервиса. Пустые назначения уже проверяет EDT, замечание не дублируется. Pinned LS не требует Функция, Экспорт или конкретное число параметров; текст сообщения не заменяет контракт кода. Включена по умолчанию, CRITICAL/ERROR, без параметров и автоисправления. Связанные позиции, расширения и полная движковая эквивалентность LS не сертифицированы.

Фактический исходный модуль разрешается текущей BM-транзакцией, а не по наличию одноимённого метода у другого владельца. Регистр имени не учитывается. Отсутствующий/неразрешённый модуль и назначение из одних пробелов пропускаются; guard пробелов консервативный, не сертифицированное буквальное поведение LS. Процедура с несколькими параметрами остаётся чистой по контракту этой диагностики.

Маркеры относятся к каждому вложенному свойству Operation.procedureName, не к диапазону модуля upstream. Переименование/удаление метода в исходнике и BM/файловые изменения назначений пересчитываются без правки потребителя; триггер исходника — ModuleContextDefIndex.contextDef. Препроцессор/recovery, удаление/восстановление всего файла модуля и расширения не сертифицированы. Live доказывает объект/count/message, не GUI-навигацию и не движковый differential LS.
