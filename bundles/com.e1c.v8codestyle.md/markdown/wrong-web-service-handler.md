# Missing WebService operation handler

Checks that a nonempty operation procedureName refers to an existing method in its own service module. Native empty-assignment validation is not duplicated. Pinned LS does not require Function, Export or a particular formal count; do not infer those restrictions from its message. Enabled by default, CRITICAL/ERROR, no parameters or quick fix. Related locations, extensions and complete LS differential parity are not certified.

The actual source module is resolved in the current BM transaction, not inferred from a method in another owner. Method names are case-insensitive. Unresolved/missing source modules and whitespace-only assignments are skipped; the whitespace guard is conservative, not certified literal LS behavior. Procedure handlers with multiple parameters remain clean according to this rule's pinned contract.

Markers belong to each nested Operation.procedureName feature, not the upstream module range. Source-only method rename/removal and BM/file-only operation assignments revalidate without editing the consumer; the source trigger is ModuleContextDefIndex.contextDef. Preprocessor/recovery, removal/recreation of the whole module file and extension ownership are not certified. Live checks prove object/count/message, not GUI navigation or an LS engine differential.
