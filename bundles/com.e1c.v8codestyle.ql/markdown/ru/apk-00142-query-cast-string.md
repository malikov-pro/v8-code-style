# Использование ВЫРАЗИТЬ(... КАК СТРОКА(N)) в запросах

При вычислении выражений в запросах — в частности, при сравнении значений,
группировке и получении различных — реквизиты строк неограниченной длины
необходимо выражать как строку определённой длины, такой, чтобы выражение
было вычислено верно: `ВЫРАЗИТЬ(... КАК СТРОКА(1000))`.

Следует иметь в виду, что частое приведение неограниченной строки к
определённой длине в запросах и отчётах СКД может быть признаком неверного
проектного решения и служить сигналом для пересмотра типа строкового
реквизита в пользу ограниченной длины строки. Для полей СКД вместо
приведения в запросе следует задавать параметр «Тип значения поля»
(на закладке «Наборы данных»).

Проверка — **ручной аудит**: убедиться, что установленной длины строки
будет достаточно для верного вычисления выражения, может только
разработчик (в АПК это ручной шаг алгоритма), поэтому проверка по умолчанию
**выключена** (включается в настройках проверок), а каждый случай приведения
только помечается. Родственная проверка md-канала
`apk-00141-unlimited-string` помечает сами реквизиты неограниченной длины.

## Неправильно

Частое урезание неограниченной строки в запросах:

```bsl
Запрос = Новый Запрос(
    "ВЫБРАТЬ РАЗЛИЧНЫЕ
    |   ВЫРАЗИТЬ(Остатки.Комментарий КАК СТРОКА(1000)) КАК Комментарий
    |ИЗ
    |   РегистрНакопления.Остатки КАК Остатки");
```

## Правильно

Ограничить длину реквизита `Комментарий` в метаданных (например, 200
символов) и убрать приведение из запроса; если же неограниченная длина
оправдана — убедиться, что длины в приведении достаточно, и пересмотреть
проектное решение.
