# Флажок «Устанавливать права для новых объектов» допустим только у роли полных прав

Включена по умолчанию, SECURITY / CRITICAL. Порт диагностики BSL LS
`SetPermissionsForNewObjects` (v8std 532).

Флажок роли «Устанавливать права для новых объектов» (`setForNewObjects`) даёт
роли автоматические права на все объекты, добавленные в конфигурацию позже. Для
роли, отличной от роли полных прав, это накапливает избыточные права и передаёт
их пользователям этой роли.

Проверка сообщает о роли, у которой флажок установлен, а имени нет в параметре
`namesFullAccessRole`.

## Параметры

| Имя | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `namesFullAccessRole` | String | `FullAccess,ПолныеПрава` | Имена ролей полных прав через запятую, которым флажок разрешён (сравнение без учёта регистра) |

## Пример

```text
Роль.CustomRole
    Устанавливать права для новых объектов   = true    <- замечание
Роль.ПолныеПрава
    Устанавливать права для новых объектов   = true    <- разрешено (роль полных прав)
Роль.PlainRole
    Устанавливать права для новых объектов   = false   <- нарушения нет
```

Исправление: снять флажок у роли либо выдать недостающие права явно.

## Ограничения

- Проверяется только собственный флажок ролей конфигурации. Роли расширений
  конфигурации проверяются по тому же правилу (флажок — свойство роли), но
  отдельной обработки ролей расширений и ролей на поддержке нет.
- Второй флажок «Устанавливать права для новых полей объектов»
  (`setForAttributesByDefault`) — другое свойство и не анализируется.
- Имена ролей сравниваются без учёта регистра (идентификаторы 1С
  регистронезависимы); LS сравнивает список с учётом регистра — осознанное
  отличие порта.
- Маркер ставится на саму роль (её флажок), тогда как LS отмечает диапазон
  модуля управляемого приложения один раз на конфигурацию.
