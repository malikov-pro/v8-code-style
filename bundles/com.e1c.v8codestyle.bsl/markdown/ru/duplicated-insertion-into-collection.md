# Повторное добавление/вставка значений в коллекцию

Включена по умолчанию, CODE_STYLE / MAJOR. Порт диагностики BSL LS
`DuplicatedInsertionIntoCollection`.

Значение, вставленное в коллекцию дважды без изменений между вставками, — это
либо ошибка копирования, либо лишний вызов: значение в коллекции уже есть.
Проверка сообщает о второй вставке.

## Что считается вставкой

- Оператор-вызов вида `Коллекция.Метод(...)`; вызов без коллекции
  `Метод(...)` не рассматривается.
- Имя метода — ровно `Вставить`/`Добавить`/`Insert`/`Add` (без учёта регистра).
  Параметр LS `isAllowedMethodADD` не портирован: используется поведение LS по
  умолчанию (метод `Добавить` тоже анализируется).
- Значение — **первый** фактический параметр. Сравнивается по тексту токенов
  (пробелы не учитываются), без учёта регистра вне строковых литералов.
  `Неопределено`/`0`/`Символы.*` и пустой параметр или пустая строка не
  участвуют.

Вставки сравниваются только внутри одного блока кода: тело модуля, тело метода,
одна ветвь `Если`/`ИначеЕсли`/`Иначе`, тело цикла или ветвь `Попытка`/`Исключение`.
Вставки в разных ветвях не сравниваются.

Пара вставок не считается нарушением, если между ними значение или коллекция
могли измениться:

- присваивание коллекции или её родителю (`Объект.Коллекция = ...`, `Объект = ...`);
- присваивание значению или любой его родительской части (`Строка = ...`,
  `Данные.Реквизит = ...` для значения `Данные.Реквизит.Поле`);
- `Возврат`/`Прервать`/`Продолжить`/`ВызватьИсключение`;
- другой вызов между вставками, передающий коллекцию или значение параметром
  (вызов может их изменить).

## Пример

```bsl
Процедура Заполнить(СтрокиИсточника)

	Строки = Новый Массив;
	Строки.Добавить(СтрокиИсточника);
	Строки.Добавить(СтрокиИсточника); // замечание: одно и то же значение добавлено дважды

КонецПроцедуры
```

Для структуры отслеживается ключ — как в LS: две вставки `Вставить("Ключ", ...)`
с одним ключом помечаются, даже если второй параметр различается.

## Ограничения

- Нет анализа потока данных и CFG: проверяются только операторы между вставками.
  Изменение значения внутри вызванного метода, через параметр или глобальную
  переменную не отслеживается.
- Правило «значение передано параметром» смотрит только корневой идентификатор
  аргумента, поэтому изменение через более длинное выражение может быть
  пропущено.
- Ветви препроцессора (`#Если`/`#If`) не объединяются так, как их объединяет
  парсер LS.
- `Прервать`/`Продолжить` во внутреннем цикле между вставками считается
  изменением, тогда как LS игнорирует прерывание, принадлежащее объемлющему циклу.
- Параметр LS `isAllowedMethodADD` не реализован.
- Одноимённые переменные в разных областях видимости считаются одним значением
  (сравнение по тексту, как в LS).
