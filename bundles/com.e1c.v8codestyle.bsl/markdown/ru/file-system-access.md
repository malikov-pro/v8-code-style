# Аудит доступа к файловой системе

Opt-in проверка SECURITY/MAJOR глобальных файловых вызовов и конструкторов
по pinned BSL Language Server FileSystemAccess. Выключена по умолчанию.
Замечание указывает место для аудита, а не доказывает уязвимость. Быстрого
исправления нет. Проверка не исполняет код и не обращается к файлам.

Параметры `globalMethods` и `newExpression` — Java regex: полное совпадение имени,
без учёта регистра RU/EN. По умолчанию сохранены все списки LS, включая асинхронные
файловые API и устаревшие типы. Методы объектов исключены, даже если имя совпало
с `globalMethods`. Для вызова выделяется имя, для конструктора — всё выражение.
Проверяются методы и тело модуля.

Динамический `Новый("Файл")` использует общую pinned-семантику: имя берётся
из первого строкового литерала первого аргумента, пробелы по краям удаляются.
`Новый("File" + Суффикс)` отмечается, строка в скобках и переменное имя типа
не вычисляются. Это не вычисление констант и не анализ потока данных.

Пустой regex не совпадает с непустыми именами. Ошибочный regex даёт предупреждение
в журнале и отключает только свою ветку на данном проходе валидации; вторая
ветка продолжает работать.

`КаталогВременныхФайлов` намеренно сохранён в `globalMethods`. Если включены
и этот аудит, и `temp-files-dir`, на вызове могут появиться два сообщения.
Автодедупа и изменения чужих настроек нет; можно включать только широкий аудит,
если узкое сообщение не нужно. Проверки удаления файлов, синхронных вызовов
и файловых операций АПК ищут другие нарушения и остаются независимыми.

Источник: [BSL Language Server: FileSystemAccess](https://1c-syntax.github.io/bsl-language-server/diagnostics/FileSystemAccess/).
