# Конфликт имени переменной и общего модуля

Проверка ищет простые присваивания, где идентификатор слева совпадает с именем
общего модуля без учёта регистра. Условия доступности взяты из `АПК_01218`
(диагностика `acc_1435`, источник — АПК 1.2.9.124).

## Правила контекста

- Потребитель — общий модуль: Сервер+ВызовСервера проверяет все общие модули;
  Сервер без ВызовСервера — серверные; иначе — клиентские управляемого приложения.
- Модули объекта, менеджера, набора записей, сеанса, обычного приложения и
  менеджера значения проверяют серверные общие модули.
- Остальные модули: &НаКлиенте/&НаКлиентеНаСервере* проверяет клиентские или
  ВызовСервера; &НаСервере* — серверные. Метод без директивы в этой ветке не
  даёт совпадения. Тело модуля использует серверный контекст. Только в этой
  ветке одноимённый формальный параметр со значением по умолчанию исключает
  все присваивания его имени внутри метода.

## Охват и отличия

Включена по умолчанию, ERROR / CRITICAL, без параметров и быстрых исправлений.
Проверяются базовые конфигурации; расширения исключены. Штатная EDT может дать
свои замечания на тот же конфликт. Автоматического отключения проверок нет.

Используется синтаксическая модель присваиваний, а не построчный поиск АПК.
Строки, комментарии, объявления, значения параметров по умолчанию, запись
в поле/индекс и чтения сами по себе не отмечаются. Присваивания внутри строки
кода учитываются. Зависимость кеша таблицы АПК от порядка модулей объекта не
воспроизводится. Полная текстовая эквивалентность АПК или LS CommonModuleAssign
не заявляется. Замечание привязано к идентификатору слева.
