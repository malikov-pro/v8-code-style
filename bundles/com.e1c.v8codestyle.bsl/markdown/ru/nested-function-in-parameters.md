# Инициализация параметров методов и конструкторов вызовом вложенных методов

Включена по умолчанию, CODE_STYLE / MINOR. Порт диагностики BSL LS
`NestedFunctionInParameters`.

Вложенные вызовы в фактических параметрах усложняют чтение: сначала нужно
вычислить внутренний вызов и удержать его результат в голове. Проверка сообщает
о внешнем вызове.

## Что считается нарушением

Вызов попадает в замечание, когда одновременно выполнено:

- выражение вызова занимает больше одной строки (вызов, записанный в одну
  строку, не проверяется);
- у вызова есть фактические параметры;
- в параметрах есть недопустимый вложенный вызов: любой вызов с получателем
  (`Объект.Метод(...)`), конструктор хотя бы с одним непустым аргументом
  (`Новый Массив(...)`), или глобальная функция, имени которой нет в
  `allowedMethodNames`;
- хотя бы один фактический параметр сам занимает несколько строк. При
  `allowOneliner=false` последнее условие не требуется.

Маркер ставится на имя метода (или на имя типа конструктора) — как в LS.

## Параметры

| Имя | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `allowOneliner` | Boolean | `true` | Разрешить однострочные выражения: при `true` вложенный вызов помечается, только если какой-то параметр занимает несколько строк; при `false` помечается любой вложенный вызов в многострочном вызове |
| `allowedMethodNames` | String | `НСтр,NStr,ПредопределенноеЗначение,PredefinedValue` | Имена глобальных функций через запятую, которыми разрешено инициализировать параметры (сравнение без учёта регистра) |

## Пример

```bsl
Процедура Заполнить(Объект, Ссылка, Коллекция)

	// замечание: параметр занимает две строки и содержит вложенный вызов
	Объект.Заполнить(Объект.ПолучитьЗначение(
		Ссылка));

	// не замечание: всё в одной строке
	Объект.Заполнить(Коллекция, Объект.ПолучитьЗначение(Ссылка));

	// не замечание: НСтр в белом списке
	Объект.Заполнить(НСтр(
		"ru = 'Текст'"));

КонецПроцедуры
```

## Ограничения

- Конструктор с типом, заданным выражением, `Новый(Тип("..."), ...)`, не
  анализируется: в модели EDT у него нет типизированного списка аргументов.
- Имя типа конструктора берётся из записанного токена, поэтому тип через
  псевдоним помечается так, как записан.
- Проверяется только список параметров вызова; выражения `Возврат`,
  присваиваний и условий вне области действия, как и в LS.
