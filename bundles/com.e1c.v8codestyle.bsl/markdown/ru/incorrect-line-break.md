# Неправильный перенос выражения

Включена по умолчанию, CODE_STYLE / TRIVIAL. Порт диагностики BSL LS
`IncorrectLineBreak`.

Перенос перед бинарным или логическим оператором читается лучше, чем после
него, а закрывающая скобка, точка с запятой и запятая принадлежат предыдущей
строке. Проверка сообщает о переносах в обе стороны.

## Что считается нарушением

Проверка работает по строкам исходного текста, как LS:

- **начало строки**: строка, соответствующая `^\s*(:?<listOfIncorrectFirstSymbol>)` —
  по умолчанию начинается с `)`, `;`, `,` без пробела после запятой или `);`;
- **конец строки**: строка, соответствующая `\s+(:?<listOfIncorrectLastSymbol>)\s*(?://.*)?$` —
  по умолчанию заканчивается на `ИЛИ`, `И`, `OR`, `AND`, `+`, `-`, `/`, `%`, `*`;
  завершающий комментарий после оператора допускается.

Сообщается найденный фрагмент; оба правила регистронезависимы, на одну строку
на каждое правило — один маркер.

## Что пропускается

- Совпадение внутри комментария к строке.
- Совпадение внутри строкового литерала (LS проверяет строку своим выражением
  для строк).
- Строка перед многострочным строковым литералом: конкатенация текста запроса
  (`Текст = Текст +` / `"ВЫБРАТЬ ..."`) не помечается.

## Параметры

| Имя | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `checkFirstSymbol` | Boolean | `true` | Проверять начало строки |
| `listOfIncorrectFirstSymbol` | String | `\)|;|,\s*\S+|\);` | Символы через вертикальную черту, с которых не должна начинаться строка |
| `checkLastSymbol` | Boolean | `true` | Проверять конец строки |
| `listOfIncorrectLastSymbol` | String | `ИЛИ|И|OR|AND|\+|-|/|%|\*` | Символы через вертикальную черту, на которые не должна заканчиваться строка |

## Пример

```bsl
// замечание: оператор в конце строки
Итог = ПервоеЗначение +
	ВтороеЗначение;

// замечание: строка начинается с закрывающей скобки
Значение = ?(ПервоеЗначение > 0,
	ПервоеЗначение,
	ВтороеЗначение
	);

// не замечание: оператор в начале следующей строки
Итог = ПервоеЗначение
	+ ВтороеЗначение;
```

## Ограничения

- LS пропускает строку перед разобранным **запросом**; порт пропускает строку
  перед любым многострочным строковым литералом — это шире (отклонение
  зафиксировано).
- Совпадение внутри строки, начавшейся на предыдущей строке, распознаётся лишь
  настолько, насколько его видит построчное выражение для строк.
- Проверка чисто текстовая и не использует AST; строки внутри директив
  препроцессора проверяются как обычный текст.
