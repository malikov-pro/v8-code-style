# Сборка для EDT 2026.2.2

Поддерживается только **EDT 2026.2.2.21 / Linux GTK x86_64 / Java 25**.
Основной вход — `bash compile.sh`; `--profile edt-2026.2` остаётся алиасом
того же режима. Старые платформы не поддерживаются.

## Публичная платформа

Штатная сборка скачивает EDT из публичного `ruby/2026.2`, дополнительные
библиотеки — из Orbit 4.38.0, Eclipse 2025-12 и Eclipse license repository.
Установленная EDT, приватный архив и secret `EDT_P2_ARCHIVE_URL` не нужны.
Все четыре HTTPS-источника перечислены в `targets/default/default.target`.

`targets/default/public-platform-lock.json` фиксирует SHA-256 метаданных
content/artifacts каждого источника; корневые IU в target имеют точные версии.
До Maven `scripts/verify-public-platform.py` проверяет доступность и хеши обоих
дескрипторов, наличие всех корневых IU и SHA-256 в метаданных каждого артефакта.
Файлы платформы загружает Tycho, используя p2 download checksums. Проверка
метаданных сама по себе не означает, что все бинарники уже скачаны и проверены.

При недоступности источника или изменении метаданных сборка останавливается;
автоматического обновления lock и перехода на локальный snapshot нет. Для
обновления платформы требуется отдельно проверить изменения зависимостей,
повторить холодную сборку, полный тестовый гейт и live сохранённого p2.
Публичный URL mutable: preflight проверяет состояние на момент запроса,
не превращает upstream в неизменяемое хранилище и не устраняет гонку с его
обновлением во время Maven. При таком обновлении сборку следует остановить
и заново проверить lock; не принимать новый набор зависимостей молча.

Для тестовой среды явно включены `org.apache.felix.scr`, `org.eclipse.swt.svg`
и `org.eclipse.equinox.event`: одного присутствия IU в target недостаточно для
попадания провайдера generic capability в зависимости тестового проекта.
Обязательные capabilities не удаляются; manifest EDT не патчится.

## Исторический приватный снимок (не штатный источник)

26 октября публичный ruby/2026.2 временно не отдавал метаданные. Для продолжения
работы был подготовлен приватный снимок установленной EDT. 28 октября публичный
источник снова доступен; снимок сохранён как отдельная страховка и не используется
новым target. Бинарники EDT не включаются в git, GitHub Release или Pages.

`targets/default/platform-lock.json` фиксирует версию, окружение, SHA-256
`content.jar`/`artifacts.jar` и SHA-256 канонического списка всех артефактов.
`scripts/prepare-platform.py` проверяет каждый файл, в том числе артефакты без
checksum в p2. Снимок с другим составом отвергается, а не обновляет lock сам.
Этот прежний lock не заменяется публичным и не обновляется автоматически.
`prepare-platform.py` остаётся утилитой проверки/импорта исторического снимка;
его запуск не переключает штатный публичный target.

Проверка и импорт прежнего снимка отдельно от сборки:

```bash
python3 scripts/prepare-platform.py --source /path/to/private/p2
```

Утилита хранит снимок в `~/.cache/v8-code-style/p2-2026.2.2` и проверяет его
при повторном запуске. Путь можно изменить через `EDT_P2_CACHE`.
Исходник и общий p2-пул EDT при импорте не изменяются. Если кэш не совпал,
скрипт останавливается; повреждённый кэш надо переименовать и импортировать
проверенный снимок заново. Автоматического удаления нет.

Для переноса между разрешёнными хостами подготовить приватный tar:

```bash
python3 scripts/prepare-platform.py --verify /path/to/private/p2
tar -C /path/to/private/p2 -cf /private/platform-2026.2.2.tar content.jar artifacts.jar plugins features
python3 scripts/prepare-platform.py --archive /private/platform-2026.2.2.tar
```

Архив содержит p2-файлы в корне (без внешней папки). Символические/жёсткие
ссылки, traversal и неожиданные файлы при распаковке отвергаются; tar не
должен использовать hardlink-записи (`--hard-dereference`, если они есть).
Вместо локального архива можно передать `EDT_P2_ARCHIVE_URL` — HTTPS URL
приватного хранилища, в том числе короткоживущий подписанный URL. Скрипт не
печатает его. Не сохранять URL/токен в репозитории или свидетельствах.

### CI и релиз

Release/Pages workflow используют тот же публичный target и preflight, что
локальная сборка, без приватного secret. Maven зафиксирован на 3.9.9, JDK — 25.
Ключ кэша включает target и публичный lock. Кэш ускоряет загрузку, но не
заменяет проверку metadata. Наличие workflow не доказывает холодный GitHub pass;
удалённый запуск, push и публикация выполняются только по отдельному разрешению.

Этот контракт воспроизводит зафиксированный p2-снимок; он не обещает
побайтово заново опубликовать p2 из произвольной установки EDT. Исходная
публикация потребовала ремонта p2 ranges/source requirements; изменение
lock — отдельная инфраструктурная задача с новым полным гейтом.

## Тулчейн и тесты

- Полный JDK 25 с `javac`, Maven **3.9.9**, Python 3.11+.
- `compile.sh --java-home /path/jdk --maven-home /path/maven` либо JAVA_HOME.
- Surefire использует ту же JVM25 (`useJDK=SYSTEM`), поддельный java17
  toolchain больше не требуется. JavaFX нужен живой EDT для UI-карточек,
  а не headless-компилятору.
- Targeted: `bash scripts/test-check.sh TestClass --module bsl`.
- Канал: `bash scripts/test-check.sh '*' --module ql`.
- Полный гейт: `bash compile.sh` под доступным X-сервером (например Xvfb),
  `NO_AT_BRIDGE=1`. Только один Maven в checkout, входы не менять до конца.
- Сохранять snapshot/hash, XML семи модулей, exit code и p2 перед следующей
  сборкой. Сборка без тестов не доказывает диагностику; новый JAR — новый live.
