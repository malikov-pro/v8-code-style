# Сборка для EDT 2026.2.2

Поддерживается только **EDT 2026.2.2.21 / Linux GTK x86_64 / Java 25**.
Основной вход — `bash compile.sh`; `--profile edt-2026.2` остаётся алиасом
того же режима. Старые платформы не поддерживаются.

## Приватная платформа

Публичный ruby/2026.2 p2 недоступен. Вместо обращения к нему используется
проверенный приватный p2-снимок. Он не включается в git, GitHub Release или
Pages: там публикуется только плагин, не дистрибутив EDT.

`targets/default/platform-lock.json` фиксирует версию, окружение, SHA-256
`content.jar`/`artifacts.jar` и SHA-256 канонического списка всех артефактов.
`scripts/prepare-platform.py` проверяет каждый файл, в том числе артефакты без
checksum в p2. Снимок с другим составом отвергается, а не обновляет lock сам.
В target используется `${env_var:EDT_P2_REPOSITORY}`, без путей конкретного
пользователя. Скрипты сборки устанавливают переменную после проверки снимка.

Первый импорт из уже подготовленного репозитория:

```bash
EDT_P2_SOURCE=/path/to/private/p2 bash compile.sh --skip-tests
```

Далее снимок берётся из `~/.cache/v8-code-style/p2-2026.2.2` и заново
проверяется перед Maven. Путь к кэшу можно изменить через `EDT_P2_CACHE`.
Исходник и общий p2-пул EDT при импорте не изменяются. Если кэш не совпал,
скрипт останавливается; повреждённый кэш надо переименовать и импортировать
проверенный снимок заново. Автоматического удаления нет.

Для переноса между разрешёнными хостами подготовить приватный tar:

```bash
python3 scripts/prepare-platform.py --verify /path/to/private/p2
tar -C /path/to/private/p2 -cf /private/platform-2026.2.2.tar content.jar artifacts.jar plugins features
EDT_P2_ARCHIVE=/private/platform-2026.2.2.tar bash compile.sh --skip-tests
```

Архив содержит p2-файлы в корне (без внешней папки). Символические/жёсткие
ссылки, traversal и неожиданные файлы при распаковке отвергаются; tar не
должен использовать hardlink-записи (`--hard-dereference`, если они есть).
Вместо локального архива можно передать `EDT_P2_ARCHIVE_URL` — HTTPS URL
приватного хранилища, в том числе короткоживущий подписанный URL. Скрипт не
печатает его. Не сохранять URL/токен в репозитории или свидетельствах.

### CI и релиз

Workflow требует secret **`EDT_P2_ARCHIVE_URL`** с доступом к тому же locked
снимку. Снимок предоставляет владелец с законным доступом к EDT. Публичного
fallback на мёртвый URL и публичной загрузки proprietary-бандлов нет.
Наличие кода workflow не означает, что secret настроен: без него холодный
runner честно завершится ошибкой подготовки платформы. Из этой задачи CI
не запускался, push/публикация не выполнялись.

Этот контракт воспроизводит зафиксированный p2-снимок; он не обещает
побайтово заново опубликовать p2 из произвольной установки EDT. Исходная
публикация потребовала ремонта p2 ranges/source requirements; изменение
lock — отдельная инфраструктурная задача с новым полным гейтом.

## Тулчейн и тесты

- Полный JDK 25 с `javac`, Maven **3.9.9**, Python 3.11+.
- `compile.sh --java-home /path/jdk --maven-home /path/maven` либо JAVA_HOME.
- Surefire использует ту же JVM25 (`useJDK=SYSTEM`), поддельный java17
  toolchain больше не требуется. JavaFX нужен живой EDT для UI-карточек,
  а не headless-компилятору.
- Targeted: `bash scripts/test-check.sh TestClass --module bsl`.
- Канал: `bash scripts/test-check.sh '*' --module ql`.
- Полный гейт: `bash compile.sh` под доступным X-сервером (например Xvfb),
  `NO_AT_BRIDGE=1`. Только один Maven в checkout, входы не менять до конца.
- Сохранять snapshot/hash, XML семи модулей, exit code и p2 перед следующей
  сборкой. Сборка без тестов не доказывает диагностику; новый JAR — новый live.
