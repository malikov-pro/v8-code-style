# CLAUDE.md — v8-code-style (форк malikov-pro)

Кодекс проекта и полные правила — [AGENTS.md](AGENTS.md) (загружать его
первым, этот файл — зеркало-указатель). «Как делать правильно» — скиллы
в `.claude/skills/`.

| Скилл | Когда |
|---|---|
| `v8cs-build` | сборка (`bash compile.sh`), профили EDT 2026.1/2026.2, ошибки резолва таргета/сети |
| `v8cs-deploy` | деплой в тестовые EDT, запуск с правильной `-vm`, триаж журнала, pgrep-самострел |
| `v8cs-release` | релиз тегом, GitHub Release, Pages-сайт, защита среды github-pages, зомби-прогоны |
| `v8cs-apk-db` | реестр АПК (`apk.db`) и живые запросы к базе АПК через MCP |
| `v8cs-port-check` | конвейер переноса проверки АПК в форк (взятие правила → тест → портед) |

## Краткий кодекс «чего не делать»

- Не поднимать JavaSE/BREE обратно на 25 — профили держатся на едином 17.
- Не пинить версию таргет-артефакта в pom — только `${project.version}`.
- Не делать второй mvn-прогон по живому дереву во время сборки.
- Не удалять jar из `~/.p2/pool` при работающей EDT.
- Не запускать EDT 2026.2 без `-vm` на полной Java 25 (ломает карточки всех
  провайдеров — см. AGENTS.md).
- Inline-`pgrep -f` с путями стенда — самострел; пути собирать конкатенацией.
- Не добавлять проверки, дублирующие существующие (v8-cs ↔ BSL LS ↔ АПК),
  без сверки с картой пересечений.

## Саморазвитие правил

Каждая находка (диагностированный грабль, новый API, рабочее решение)
**в этом же ходе фиксируется в AGENTS.md или скилле** — правила проекта
живут на найденном опыте. Нет раздела — создать; есть — дополнить таблицей
«симптом → причина → решение». Формат: кратко, с точными именами/путями.

Референсы соседей (не часть проекта): каталог `_ext_src/` — только чтение.
